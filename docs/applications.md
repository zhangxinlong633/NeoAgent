### 文档目的

本文说明 Neo 体系结构在产业与技术栈中的**适用场景、问题域与生态位**。论述建立在「极致灵活性与位置透明」这一核心优势之上：编排与能力契约不绑定单一运行环境、部署规模或算力等级。

文中「未来层」描述属于中长期愿景，不等同于本仓库现行交付范围。现行产品形态为轻量命令行智能体（**DAG ∥ Capability Matrix ∥ Policy**），详见 [`architecture.md`](architecture.md)、[`manual.md`](manual.md)、[`examples.md`](examples.md) 与 [`AGENTS.md`](../AGENTS.md)。

---

## 1. 核心优势与问题域

Neo 的差异化不在于追求单一场景下的模型上限，而在于：

| 特性 | 说明 |
|------|------|
| 环境无关 | 同一逻辑内核可面向云、边、端等异构载体 |
| 规模弹性 | 从单机旁路助手到（目标态）分布式节点池均可沿同一契约演进 |
| 算力自适应 | 通过能力矩阵、策略裁剪与（路线图）计算漂移匹配可用算力 |
| 位置透明 | 业务逻辑不硬编码执行场所；由调度策略决定本地或远端 |

据此，Neo 适用于各类需要 **智能体与物理世界或数字系统持续交互**、且对确定性、成本或时延有约束的场景。

---

## 2. 基础层：缓解智能体工程落地障碍

本层对应 Neo 相对「纯对话式 Agent」与「仅云端函数调用」的直接价值。

### 2.1 复杂任务的稳定执行

| 项目 | 说明 |
|------|------|
| 痛点 | 纯 ReAct 类智能体在长程任务中易偏离目标或陷入循环 |
| Neo 路径 | 以 DAG 蓝图预置或规划任务拓扑；调度层保证推进语义；执行层处理单步结果与失败回传 |
| 典型流程 | 获取数据 → 清洗 → 分析 → 通知（多步骤可复现、可审计） |
| 现行基础 | 本机 `workflow` / `plan` / `run`；完整自动降级与分布式调度见架构路线图 |

### 2.2 工具调用的工程化治理

| 项目 | 说明 |
|------|------|
| 痛点 | 云端 Function Calling 难以统一管理海量企业内部接口与遗留系统 |
| Neo 路径 | Capability Matrix 登记原子能力；支持命令、内建、MCP 等装载方式；目标态支持多态实现（本地脚本、远端应用程序接口、容器化实现等） |
| 适用对象 | 企业内部 SOAP、遗留数据库、脚本资产、受控命令行工具等需被智能体调用的接口集合 |
| 现行基础 | `capability_matrix`、`capabilities/`、MCP stdio；企业级权限与审计总线为路线图 |

### 2.3 成本与时延的可控性

| 项目 | 说明 |
|------|------|
| 痛点 | 凡推理皆回传云端大模型，导致带宽、时延与费用失控 |
| Neo 路径 | （目标）计算漂移：轻量处理优先本地执行，高难度推理再调用远端模型 |
| 期望效果 | 降低运营成本，缩短简单任务的往返时延 |
| 现行基础 | 本机能力执行与远端大语言模型调用可并存；独立位置决策引擎为路线图 |

## 3. 行业层：边缘、具身与物联网

本层体现 Neo 相对「纯云端 Agent」的差异化战场，尤其面向资源受限装置。

### 3.1 工业边缘智能

| 项目 | 说明 |
|------|------|
| 典型场景 | 产线机器视觉质检、可编程逻辑控制器侧的异常预测与联锁 |
| 架构用法 | 规划层可部署于工控主机；执行层下沉至摄像头、控制器等节点（目标部署形态） |
| 关键价值 | 网络中断时，本地调度与执行仍可完成「采集 → 判定 → 执行」闭环（边缘自治） |
| 约束说明 | 需满足实时性、安全隔离与现场认证要求；完整边缘自治依赖路线图中的分设部署与降级协议 |

### 3.2 具身智能与移动平台

| 项目 | 说明 |
|------|------|
| 典型场景 | 服务机器人、巡检机器人、无人机组网 |
| 架构用法 | 调度层并行推进传感相关节点（例如避障与导航）；执行层绑定机载算力上的能力原子 |
| 关键价值 | 将关键闭环保留在机载主控，降低对云端往返时延的依赖 |
| 约束说明 | 硬实时控制回路通常仍由专用控制器承担；Neo 侧重任务级编排与能力治理，而非替代底层运动控制周期 |

### 3.3 分布式物联网联动

| 项目 | 说明 |
|------|------|
| 典型场景 | 楼宇、厂区等大规模传感与执行器联动 |
| 架构用法 | 区域网关承担调度；传感与执行节点承载执行层能力（目标形态） |
| 关键价值 | 在授权策略允许时，关键联锁可不经公有云中转，缩短跨设备响应路径 |
| 约束说明 | 涉及人身与消防等安全系统时，须符合行业强制规范；Neo 作为编排层须接受上位安全认证体系约束 |

## 4. 未来层：智能基础设施形态

下列方向描述架构成熟后的可能角色，属于战略愿景，**不作为现行版本功能清单**。

### 4.1 智能体作为设备侧运行内核

设备不再仅以传统桌面或移动操作系统应用为唯一扩展单元，而以「能力包」形式注册到统一调度与执行契约之下。调度层管理任务与资源编排，执行层装载模型与工具实现。该形态要求极高的隔离、权限与供应链安全能力，远超本仓库当前范围。

### 4.2 个人或组织侧数字助理基础设施

在私有存储或网关内部署 Neo，调度浏览器、邮件、文档等能力完成日常自动化，使敏感数据默认不出信任边界。该方向与 claw（身份、规则、记忆）及本机能力矩阵高度相关；现行仓库已提供单机旁路形态的基础能力。

### 4.3 跨平台能力分发标准

当能力包格式、沙箱与矩阵契约足够稳定时，Neo 可能演进为类似「智能体侧可移植容器」的分发单元：开发者面向契约打包，运行时在多种操作系统与芯片上装载。这将依赖标准化、安全审计与生态治理，属于长期议题。

## 5. 生态位总结

| 对照物 | 角色隐喻 | 说明 |
|--------|----------|------|
| 云端通用大模型 | 高容量推理与生成 | 提供深度认知能力 |
| Neo | 设备与系统侧的编排与执行脊梁 | 使智能能够在约束条件下安全、及时、低成本地作用于数字与物理接口 |

**定位陈述**：

1. Neo **不以替代云端大模型为目标**，而以使其可被可靠编排进真实系统为目标。  
2. 在边缘计算与近数据计算需求增强的背景下，Neo 提供「云端可沉思、终端可瞬应」的分层架构路径。  
3. 本仓库优先交付可移植的单机内核与契约（DAG、矩阵、策略、可选规划）；分布式与工业级自治能力按 [`architecture.md`](architecture.md) 路线图演进。

## 6. 与现行产品的对应关系

| 场景层次 | 与现行仓库的相关性 | 主要依托 |
|----------|--------------------|----------|
| 基础层：多步骤确定性任务 | 高 | `dags/baseline/`、`neo plan` / `neo run` |
| 基础层：工作区旁路助手 | 高 | `dags/workspace/`（含旗舰 SOP `workspace_brief`） |
| 基础层：工具工程化 | 高 | `capability_matrix`、`capabilities/git/`、`capabilities/unix/`（白名单）、MCP |
| 基础层：步骤可观测 / 失败定位 | 高 | `./neo -v dag run …`；失败时 `status=fail` 含步骤类型 |
| 基础层：成本与时延优化 | 中（部分） | `type:tool` 本地能力 + `type:llm` 远端；计算漂移为远期 |
| 行业层：边缘 / 具身 / 物联网 | 低（方向正确） | 预留 `capabilities/industry/`、`dags/edge/`（默认不加载）；架构见 [`architecture.md`](architecture.md) §8.1 |
| 未来层：操作系统化 / 分发标准 | 愿景 | 非现行交付范围 |

近端优先补齐基础层可复查与可观测；行业与愿景层勿当作已交付。细则见 [`architecture.md`](architecture.md) §8.1。
