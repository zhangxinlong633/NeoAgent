## 1. 总评

相对 09-12：**基础层明显加厚**。规划失败更可解释，daemon 可挂 `-S`，可选 JSONL 事件补上可观测缺口，专业软件路径（Blender headless）有可复现样例。产品三角未漂移。

相对架构愿景：仍是**单机 CLI 基础层**；分布式 / 漂移 / 隔离仍属路线图，本期刻意未碰。

## 5. 优势（增量）

1. **规划可失败得明白** — 未知 catalog、缺 requires 有稳定 stderr，而不是 silent invent。  
2. **会话一条路径** — 交互 daemon 与具名 session 可合并，文档与实现一致。  
3. **可观测有钩子** — 一轮对话 / DAG 步骤可落 JSONL，便于后续成本与重放（尚未做）。  
4. **专业软件套餐示范** — Blender 走矩阵 + DAG，而不是另开 IDE 插件叙事。

---

## 6. 短板（仍在）

1. **愿景落差** — 架构愿景大、交付仍是单机旁路助手。  
2. **规划质量仍绑模型** — catalog-only 是闸门，不是理解力；元数据不足仍会选错。  
3. **事件未产品化** — 无 schema 版本约定、无成本字段、无失败重放工具。  
4. **DAG 深度** — 无步骤超时/重试、无最小并行。  
5. **记忆天花板** — 本地 hash embedding，跨任务长期记忆弱。  
6. **MCP 任意代码面** — Blender MCP 的 `execute_code` Neo 不按名裁剪；文档已警告，治理仍靠人。

---

## 7. 建议优先序（下一轮）

| 优先级 | 动作 |
|--------|------|
| P1 | DAG：步骤级超时 / 有限重试；无依赖边的最小并行（architecture §8.1） |
| P1 | 事件：固定字段约定 + 可选成本/token；手册一页「如何读 NEO_EVENTS」 |
| P2 | 记忆：可选外部 embedding；与 session 边界写死 |
| P2 | plan 质量：目录 `when`/`when_not` 抽检与样例强化（非再加规划引擎） |
| P3 | 分布式 / 漂移 / WASM — 仍推迟，除非有明确单机无法覆盖的场景 |

加功能前仍用 `AGENTS.md` §9 三角自检。

---

## 8. 一句话

近端一轮把「能登记、能编排、默认收着」补成了「选型可拦、会话可续、运行可记」；下一刀应切在 **DAG 深度与事件产品化**，而不是愿景层的分布式故事。
