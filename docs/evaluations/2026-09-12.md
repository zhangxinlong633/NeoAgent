### 文档目的

记录对 Neo Agent **现行交付形态**的成熟度判断、适用边界与近端优先项，便于协作者对齐「已经能干什么 / 还不该承诺什么」。目标架构愿景仍以 [`../architecture.md`](../architecture.md) 为准；日常用法以 [`../manual.md`](../manual.md) 为准。

---

## 1. 总评

作为「可治理的轻量 Agent 运行时」，产品三角 **DAG ∥ Capability Matrix ∥ Policy** 已经立住，单机 CLI 交付完整可用。

作为 [`../architecture.md`](../architecture.md) 中的「分布式弹性智能体」，仍处**基础层**：愿景大、内核小。这是刻意取舍（见 `AGENTS.md` §5 非目标），不是半成品失败。

| 维度 | 判断 |
|------|------|
| 产品定位 | 清晰 |
| 能力治理 | 扎实 |
| 编排深度 | 中等 |
| 愿景兑现 | 早期 |

规模参考（约数，会随提交变化）：自研 C 约 1 万行（不含 vendor）；`capabilities/` 百余文件；CLI 冒烟近期可通过。

## 2. 成熟度（相对自标定位）

| 层 | 状态 | 说明 |
|----|------|------|
| Capability Matrix | 扎实 | builtin / commands / MCP stdio / 目录包同源；Policy 裁剪 `enabled` |
| Policy | 够用 | shell 默认关、路径沙箱、http 白名单、轮次与字节上限 |
| DAG 执行 | 可用 | `tool` / `llm` / `loop` / `route` 串行拓扑；无并行、无检查点 |
| 规划（`plan` / `run`） | 可用 | catalog `use` 优先 + 现编；质量依赖模型与 `when` / `when_not` |
| 会话 / Daemon | 可用 | 落盘 `-S`、角色、JSON；daemon 交互 `User>` / `neo>` + Markdown / UTF-8；与 `-S` 仍独立 |
| Memory | 雏形 | 本机 hash embedding；召回可用，语义深度有限 |
| 分布式 / 计算漂移 | 愿景 | 路线图；现行明确单机 CLI |

更细的愿景对照见 [`../architecture.md`](../architecture.md) 第 8 章。

## 3. 场景匹配

| 场景 | 匹配 | 原因 |
|------|------|------|
| 仓库旁路 SOP / 状态核查 | 高 | 白名单命令 + 具名 DAG 可复现 |
| 受控工具编排（脚本 / MCP） | 高 | 矩阵装载路径完整，Policy 默认偏安全 |
| 多轮对话助手 | 中 | 会话 / daemon 够用，但不如专用 chat 产品 |
| Cursor 级编码 agent | 低 | 明确非目标；缺多文件编辑 UX 与全仓索引 |
| 工业边缘自治 / 具身 | 愿景 | 契约可演进；现行无分设调度与隔离 |

应用叙事见 [`../applications.md`](../applications.md)；其中「行业层 / 未来层」不等于已交付。

## 4. 优势

1. **定位清晰** — 不是最强 IDE agent；三角写进 `AGENTS.md`，能挡住范围膨胀。  
2. **治理先于炫技** — 能力进矩阵、Policy 守门；默认不安全能力不开。  
3. **可移植内核** — C99 + 内置 HTTPS / JSON5；换环境主要改配置。  
4. **双入口语义** — 反应式 tool loop 与确定性 DAG 共用同一矩阵快照。  
5. **文档分层** — 手册 / 样例 / 架构愿景分开；成熟度表相对诚实。

---

## 5. 短板

1. **愿景落差** — 架构文写边缘 / 漂移 / WASM；交付仍是单机旁路助手。  
2. **规划脆弱** — `plan` 随模型波动；目录元数据不足时易胡编 DAG。  
3. **会话分裂** — daemon 内存历史与 `-S` 落盘两套语义，用户易混淆。  
4. **可观测性薄** — 有 `-v` / `-d`，缺结构化 trace、失败重放、成本统计。  
5. **记忆天花板** — 本地向量维度低、无真 embedding；跨任务长期记忆弱。  
6. **文档漂移风险** — 架构对照若残留旧路径，需持续回写第 8 章。

---

## 6. 建议优先序

| 优先级 | 动作 |
|--------|------|
| P0 | 收紧 `plan`：强制 / 优先 catalog `use`、校验 `requires`、失败可解释 |
| P0 | 统一会话叙事：daemon 可选挂 `-S`，或文档写死「两套」并给迁移路径 |
| P1 | DAG：步骤级超时 / 重试；无依赖边的最小并行 |
| P1 | 可观测：一轮对话 / 一步 DAG 的结构化 stderr 或 JSONL 事件 |
| P2 | 记忆：可选外部 embedding；与 session 明确边界 |
| P2 | 架构文档第 8 章与源码路径对齐，减少愿景误读 |

加功能前仍应用三角自检（见 `AGENTS.md` §9），避免并行第二套工具名字空间或默认打开 `shell_enabled`。

---

## 7. 一句话

Neo 现在是一把「刀刃可登记、刀柄可换、默认收着」的瑞士军刀运行时；锋利处在**治理与可移植**，不在模型上限或 IDE 体验。继续演进时，优先夯实基础层（规划、会话、可观测），而不是追路线图里的分布式故事。
